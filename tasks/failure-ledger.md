## 2026-08-09 — 다른 PC 클론이 CRLF 라, 돌연변이 6건이 조용히 '검정 불성립'으로 빠졌다
- 시도: 이 레포를 새 PC(C:\Users\Admin)에 clone 한 뒤 tests/mutate.py 를 돌렸다
- 실패 이유: git 의 core.autocrlf=true 로 작업 트리가 CRLF 로 체크아웃됐는데, 돌연변이 앵커 중 **여러 줄짜리**는 LF(`\n`) 로 적혀 있어 하나도 안 맞았다. 그 6건은 FAIL 도 MISS 도 아닌 INVALID 로 빠지는데, 이건 "게이트가 실패를 잡는지 확인하지 않았다" 는 뜻이라 조용히 검정 구멍이 된다. 원인이 코드가 아니라 체크아웃 설정이라 소스를 아무리 봐도 안 보인다
- 대안·다음엔: (1) 작업 트리를 LF 로 정규화, (2) `.gitattributes` 에 `* text=auto eol=lf` 를 박아 어느 PC에서 clone 해도 LF 로 오게 함, (3) build.py 가 dist 를 쓸 때 `newline='\n'` 을 명시 — 기본값은 os.linesep 이라 배포본 바이트가 플랫폼에 따라 달라진다. 앵커를 LF 로 유지하는 대신 환경을 고정하는 쪽을 골랐다
- 재사용 자산: .gitattributes(사유 주석 포함) · 앵커 점검 한 줄 — mutate.py 를 import 해 MUTATIONS 를 돌며 `src` 파일에서 find 문자열이 정확히 1회인지 세면 실행 전에 갈린다
- 참조: [[logic-foundry-game]]

## 2026-08-09 — 씨앗 심기가 자기 목적을 배반했다 (평활 필터, 배선 전 y=0 고착)
- 시도: 평활 필터의 첫 평가에서 `n.state.y = xs` 로 입력값을 씨앗으로 심어, 이미 돌던 신호에 필터를 물릴 때 생기는 0→현재값 과도를 막으려 했다
- 실패 이유: 사람이 노드를 만드는 유일한 경로는 팔레트 클릭이고, 그 순간 노드는 **배선 없이** 생긴다. 편집기를 열어도 시뮬은 계속 돌고 고립 노드도 평가되므로, 16.7ms 안에 readIn=0 인 채로 첫 평가가 돌아 y=0 이 박힌다. 그 뒤 배선하면 y 가 이미 유한수라 재씨앗이 안 되고, 막으려던 과도가 정확히 그 자리에서 생긴다. τ=10·재고 60·임계 50 이면 거짓 경보가 17.9초 켜진다. 게이트 4종이 전부 배선을 첫 틱 **전에** 끝내고 입력을 0 으로 뒀기 때문에 "입력값 씨앗"과 "0 씨앗"이 구별되지 않았다 — 통과 케이스만 있는 게이트였다
- 대안·다음엔: 같은 파일의 출력 노드들이 이미 쓰는 규약(`if (!inputFed(g, n, 0)) break;`)을 상태를 가진 연산 노드에도 적용한다 — 안 물린 동안은 씨앗을 심지 말고 state 를 지운다. **상태를 초기화하는 코드를 쓸 때는 "그 초기화가 도는 시점에 입력이 이미 있는가"를 먼저 묻는다**
- 재사용 자산: 게이트 smooth.seedsFromRealInputWhenWired(배선 전/후를 갈라 재는 형태) + 음성 대조군 smooth.wiredStepStillFilters

## 2026-08-09 — 저장 게이트가 두 결함의 상쇄로 GREEN 을 냈다 (상태기계)
- 시도: 상태기계 저장/복원을 "2단계에서 저장 → 복원 후에도 2단계" 로 검사했다
- 실패 이유: 저장 시점에 네 전이 조건이 전부 참으로 붙들려 있었다. 노드 상태를 통째로 잃은 구현은 복원 시 1단계로 초기화되고, 붙들린 조건이 상승엣지로 읽혀 즉시 한 칸 튀어 **정확히 2단계**에 도착한다. 게이트는 2 == 2 를 보고 통과한다. 상태를 잃는 것과 헛전이하는 것, 결함 둘이 서로를 가렸다
- 대안·다음엔: 저장/복원 검사는 **초기화 기본값에서 한 칸 떨어진 상태를 고르지 않는다.** 3단계에서, 그리고 전이 조건을 내린 채 저장한다. 그리고 "단계가 남는가"와 "엣지 기억이 남는가"를 한 단언에 뭉치지 말고 쪼갠다 — 조건을 든 채 저장하는 별도 검사가 pe 손실을 잡는다
- 재사용 자산: fsm.survivesSave(조건 내림·3단계) + fsm.saveKeepsEdgeMemory(조건 유지·4단계) 두 갈래 형태
