# 엔진 하나에서 GREEN 은 "동작한다"가 아니라 "Chromium 에서 동작한다"이다

게이트 84건(모델 57 + 클릭 27)이 전부 GREEN이었지만 전부 Edge 하나에서였다.
Canvas2D 변환·합성 이벤트·`localStorage`·TypedArray base64 왕복은 엔진마다 다르게 굴 수
있는 대표적인 자리라, 그 상태로는 "이 게임이 동작한다"를 주장할 수 없었다.

## 걸림돌: 판정 채널이 엔진에 묶여 있었다

하네스는 Chromium 전용 스위치 `--dump-dom` 으로 `#testout` 을 읽고 있었다. Firefox 헤드리스에는
그 스위치가 없다. 여기서 흔한 실수는 **엔진마다 별도 채점기를 만드는 것** — 그러면 결과가
갈렸을 때 어느 쪽이 맞는지 알 수 없다.

한 일: 읽는 방법만 갈아끼우고 **판정 로직은 `harness.py` 한 곳에 그대로 뒀다.**

```
harness.py <드라이버> <엔진>
  edge                     → --dump-dom (기존 경로)
  chromium/firefox/webkit  → tests/pwrun.js (Playwright 로 #testout 을 직접 읽음)
```

드라이버도 게이트도 손대지 않았다. 바뀐 것은 "페이지에서 JSON 을 꺼내는 방법" 뿐이다.

## 결과

엔진 4개 × 드라이버 2개 = **8조합 전부 GREEN**. 같은 장면(`tests/scene-factory.js`)을 네
엔진에서 찍어 눈으로도 대조했고, 차이는 한글 폰트 메트릭뿐이었다.

## 규칙

- **장면 스크립트도 한 파일로 공유한다.** 엔진별로 장면을 따로 두면 그림이 달라도 엔진 탓인지
  장면 탓인지 구분할 수 없다. `shots.py`(Edge)와 `pwshot.js`(나머지)가 같은 파일을 읽는다.
- **엔진 안에서 렌더를 확인한 뒤 캡처한다.** `pwshot.js` 는 스크린샷 전에 `__PIXEL_PROBE` 로
  색 수를 재고 엔티티 수를 함께 찍는다 — 빈 그림을 "촬영 성공"으로 세지 않기 위해서다.
- Windows 에서 Safari 는 돌지 않는다. **WebKit 엔진은 대용이지 실기가 아니다** — 그렇게 적는다.
