# 되먹임이 있는 제어를 순진하게 배선하면 발진한다 — 게임의 주제이자, 내가 테스트에서 그대로 밟은 함정

부하 차단 게이트를 이렇게 짰다: `전력 만족도 >= 95 이면 저우선 라인 가동`.
결과는 "0대 꺼짐". 원인은 버그가 아니라 **제어 구조**였다.

```
만족도 73% → 4대 차단 → 수요 감소 → 만족도 100% → 즉시 복구 → 만족도 73% → …
```

60 Hz로 이 순환이 돌아 표본을 뜨는 순간마다 상태가 달랐다. 측정값은 "차단 안 됨"으로 보였다.

## 두 가지가 함께 필요하다

1. **상태를 기억한다 (SR 래치).** 차단 여부를 매 틱 조건에서 다시 계산하지 않는다.
2. **복구를 늦춘다 (타이머).** 회복되자마자 되돌리면 원인이 곧바로 재발한다.

```
만족도 < 95  ──────────────► SET  ┐
                                  ├─ 래치 Q(=차단 중) ─► NOT ─► 라인 가동
만족도 > 99 ─┐                    │
타이머 30초 ─┴─ AND ─────────► RESET ┘
```

이 배선은 안정된다: 차단 후 만족도가 100%로 올라도 타이머가 울리기 전까지 래치가 유지된다.
게이트도 "1초 뒤 4대 차단" 뿐 아니라 **"3초 더 돌려도 그대로"** 를 함께 본다 — 그게 발진과
정상 동작을 가르는 유일한 검사다.

## 게임 설계에도 반영했다

제어기가 **전기를 쓰지 않게** 바꿨다. 전력을 요구하면 "전력이 부족할 때 부하를 차단하는"
배선이 자기 전원을 끊는 순간 제어기가 죽고, 지배가 풀려 라인이 다시 켜지고, 또 죽는다.
Factorio의 회로망도 같은 이유로 무전력이다. 아울러 `enable` 출력이 **자기 제어기**를
가리키면 무시하도록 막았다.

## 일반화

- 되먹임 루프의 게이트에는 **정상상태 검사**를 반드시 넣는다. 한 시점만 보면 발진을 통과시킨다.
- 제어 대상이 측정값에 영향을 주면(= 폐루프) 히스테리시스나 지연 없이 임계값 비교만 쓰지 않는다.
- 이건 사용자(모터·제어 전공)에게는 익숙한 이야기다. 그래서 이 게임의 핵심 학습 지점으로
  도움말에 명시해 두었다.
